# ml — процессинг инструкций

```
python3 fix_raw_md.py   # разово: чинит артефакты нумерации в raw-md/*.md (идемпотентно)
python3 process.py      # читает raw-md/*.md, пишет jsons/ (рядом с raw-md/)
```

Вывод `process.py`:

```
jsons/
  instrukciya-po-rabote-s-portalom-dlya-postavshchika.json
  instrukciya-po-rabote-s-portalom-dlya-postavshchika/
    image-1.png
    image-2.png
```

Один `.md` → один `.json` с именем `slug(название .md)` (транслит в латиницу: `Инструкция по работе с МЧД` → `instrukciya-po-rabote-s-mchd`).

## Формат json

Плоская мапа нод, ключи — `"root"` и `"x.x.x"` (глубина = количество цифр):

```json
{
  "root": { "heading": "ИНСТРУКЦИЯ ДЛЯ ЗАКАЗЧИКА...", "text": "...", "children": ["2", "3"] },
  "2":    { "heading": "Общие сведения о портале поставщиков", "text": "...", "children": ["2.1"] },
  "2.1":  { "heading": "Описание общего процесса...", "text": "...", "children": [] }
}
```

- `text` — весь markdown между этим заголовком и следующим `## x.x.x` (включая таблицы и заголовки без id,
  например `## Таблица 2 - ОПО АРМ пользователей`).
- Глубина ключа всегда равна глубине ноды в дереве (проверяется ассертом в конце прогона).
- На случай, если дубликаты id всё же появятся в новом raw-md, `process.py` не теряет их, а даёт ключи `18#2`, `18#3`.

## Картинки

Подпись `Рисунок N - <caption>` → файл `<slug>/image-N.<ext>`, а ссылка в тексте становится

```
![<caption>](__IMG_PREFIX__/<slug>/image-N.png)
```

`__IMG_PREFIX__` — плейсхолдер, подставляйте свой base URL (тогда картинки отдаются как `<base>/<slug>/image-N.png`).

Нюансы:

- В исходных md подпись чаще **под** картинкой, реже над — пара ищется по соседству (между ними только пустые строки),
  приоритет у картинки сверху.
- Картинка без подписи (иконки, артефакты PDF) получает id после максимального номера рисунка в документе.
- Если у одного рисунка несколько картинок: `image-176.png`, `image-176-2.png`.

## Правки исходников (`fix_raw_md.py`)

В PDF-выгрузках встречаются артефакты нумерации: повторяющиеся id (блок «Банковские гарантии» начинался
заново с `## 1`, `## 2`…), заголовки без номера (`## 14.2.2`, потом титул отдельной строкой) и заголовок
раздела, напечатанный после своего же подраздела (`## 22 Контракты`). Скрипт правит только эти строки
(что именно и на каких строках — печатает при запуске) и повторный запуск ничего не делает.

## Проверка

После прогона: все ссылки `__IMG_PREFIX__` резолвятся в существующие файлы, лишних файлов нет,
все ноды достижимы из `root` (проверялось скриптом-ассертом на текущем корпусе).

# Агент по мануалам + HTMX-админка + REST API

```
cp .env.example .env    # вписать DEEPSEEK_API_KEY и ключи Langfuse
uv sync
uv run uvicorn app:app --port 8010   # админка и API (8000 занят mpfit)
uv run python main.py                # то же самое в терминале
```

Аутентификации нет: чаты общие, доступ по id.

## Модули

| файл | что делает |
|---|---|
| `manuals.py` | читает `jsons/`, разворачивает плоскую мапу в `Section` (+ предки), рендерит деревья и `open`-ответы |
| `rag.py` | эмбеддинги/LLM, chroma-индекс разделов, fuse-поиск, инструменты `search`/`open`, агент, Langfuse |
| `storage.py` | SQLite-хранилище: чаты, сообщения, вызовы инструментов (`chats.sqlite3`) |
| `chat.py` | общий слой чата: запись хода в БД + стрим событий агента (`start`/`token`/`tool_call`/`tool_result`/`done`) |
| `api.py` | REST API `/ml-api/chat ...` (типизирован, документирован) |
| `support.py` | линии поддержки: мануал + тул перевода, закрытие чата (заглушка) |
| `assets.py` | отдаёт картинки мануалов: `GET /ml-assets/image/<slug>/<filename>` |
| `app.py` | FastAPI: HTMX-админка + подключение REST API и Swagger |
| `main.py` | CLI-болталка с тем же агентом |
| `pyproject.toml` | зависимости (uv), `.env` — ключи |

## Хранилище

Чаты лежат в SQLite (`chats.sqlite3`, WAL) — путь можно переопределить через `CHAT_DB_PATH`.
Три таблицы: `chats` (в т.ч. `system_prompt`), `messages`, `tool_calls`
(каскадное удаление). Схема создаётся автоматически; при breaking change базу просто
удаляют, бэкенд создаст заново.

## Стиль ответов

Системный промпт просит агента отвечать кратко (2–5 предложений). На обширный вопрос
(«расскажи всё про…») агент даёт короткую суть и задаёт уточняющий вопрос вместо стены
текста. Развёрнутый ответ — только если попросили явно («подробно», «пошагово»,
«ничего не сокращай»).

## REST API

Swagger: `/ml-api/docs`, схема: `/ml-api/openapi.json`. Роуты админки в документацию не попадают.

| метод | путь | что делает |
|---|---|---|
| `POST` | `/ml-api/chat` | создать чат (опционально `system_prompt`), вернуть `id` |
| `GET` | `/ml-api/chat` | список чатов |
| `GET` | `/ml-api/chat/<id>` | содержимое чата: сообщения + вызовы инструментов |
| `DELETE` | `/ml-api/chat/<id>` | удалить чат |
| `POST` | `/ml-api/chat/<id>/message` | отправить сообщение, SSE-стрим ответа и тулколов |
| `GET` | `/ml-assets/image/<slug>/<filename>` | картинка из мануала |

События стрима: `start` (id ответа), `token` (дельта + накопленный текст), `tool_call`,
`tool_result`, `redirect` (перевод на линию, чат закрыт — дальше `409`), `error`,
`done` (финальный текст). Ответ сохраняется в БД по ходу генерации,
поэтому обрыв соединения не теряет сгенерированное — `GET` потом вернёт текст.

### Картинки в ответах

Картинки мануалов лежат в `jsons/<slug>/image-N.png` и отдаются эндпоинтом
`GET /ml-assets/image/<slug>/<filename>` (`assets.py`, пути проверяются — `..` и чужие
каталоги блокируются, ответ кэшируется на сутки).

Инструмент `open` возвращает текст раздела с **уже подставленным префиксом**: плейсхолдер
`__IMG_PREFIX__` из `process.py` меняется на `/ml-assets/image` (см. `manuals.section_body`).
Агент видит готовые ссылки `![подпись](/ml-assets/image/<slug>/image-N.png)` и по системному
промпту референсит их прямо в ответе рядом с нужным шагом.

Рендерят обе стороны: HTMX-админка (markdown → `<img>`, стили в `static/style.css`) и
любой клиент REST API — в `content` сообщения приходит тот же markdown, а картинку можно
взять по ссылке из разметки.

```bash
curl -O http://localhost:8010/ml-assets/image/instrukciya-po-sozdaniyu-oferty-i-ste/image-1.png
```

### Дополнительный системный промпт

`POST /ml-api/chat` принимает необязательное поле `system_prompt`. Оно **не переопределяет**базовый промпт агента, а дописывается в его конец — туда можно положить контекст пользователя
от бэкенда, чтобы агент его учитывал:

```bash
curl -X POST localhost:8010/ml-api/chat \
  -H 'Content-Type: application/json' \
  -d '{"system_prompt": "Пользователь: ООО «Ромашка», поставщик, регион Москва."}'
```

Промпт хранится в БД и применяется ко всем последующим ответам этого чата. Без поля
(или с пустой строкой) используется только базовый промпт.

```bash
ID=$(curl -s -X POST localhost:8010/ml-api/chat | jq -r .id)
curl -N -X POST localhost:8010/ml-api/chat/$ID/message \
  -H 'Content-Type: application/json' \
  -d '{"message": "Как создать котировочную сессию?"}'
```

## Индексация

Один `TextNode` на раздел, **без чанкинга** (`text` как есть; если `text` пустой — в ноду идёт `heading`,
чтобы раздел-контейнер всё равно находился). Метаданные ноды:

- `manual` — slug мануала, `manual_title` — название
- `id` — `root` / `x.x.x`, `heading` — заголовок раздела
- `children` — список подразделов (в chroma кладётся как JSON-строка, у самой ноды — тоже)

Стор: `chroma_db/` (persistent chroma). Хеш корпуса лежит в `chroma_db/corpus.sha1`: если `jsons/`
изменились, индекс пересобирается сам при старте: `uv run python -c "import rag"` (на CPU ~15 мин,
в это время админку лучше не поднимать).

Внимание на двух моментах:

- **Эмбеддинги считаются на CPU** (`EMBED_DEVICE=cpu`): при `mps` на текущем torch 2.14 процесс падает
  с SIGSEGV (`at::native::mps::...copy_cast_kernel_mps`). Полная пересборка на CPU — ~15–20 мин
  (603 раздела, `BAAI/bge-m3`); в рантайме эмбеддится только запрос (~0.1 с). Для быстрой пересборки
  можно взять модель полегче: `EMBED_MODEL=sergeyzh/rubert-tiny-turbo`.
- Смена `EMBED_MODEL` требует пересборки индекса, иначе размерности векторов не сойдутся.

## Инструменты агента

В системный промпт попадают **только названия мануалов и их slug'и** — никакого дерева
разделов, и тем более текста мануала по линиям поддержки. Дальше агент ходит по инструментам:

**`search(query)`** — fuse-поиск (вектора + BM25, `QueryFusionRetriever`, 0.6/0.4) **сразу по всем
инструкциям** (slug не принимает). Возвращает **без текста**: дерево `id + heading` найденных
разделов вместе с их родителями, **сгруппированное по документам**; родители дедублицируются,
совпадения помечены `[найдено]`, соседние ветки в порядке документа:

```
Найдено 34 разделов в 6 мануалах по запросу «котировочная сессия»:

[instrukciya-po-rabote-s-portalom-dlya-zakazchika] — ИНСТРУКЦИЯ ДЛЯ ЗАКАЗЧИКА... (5 разделов):
- 8 Осуществление закупки
  - 8.2 Котировочные сессии  [найдено]
    - 8.2.1 Создание котировочных сессий через реестр...  [найдено]

[instrukciya-po-rabote-s-portalom-dlya-postavshchika] — ИНСТРУКЦИЯ ДЛЯ ПОСТАВЩИКА... (4 разделов):
- 20 Участие в закупках
  - 20.1 Котировочные сессии  [найдено]
```

**`open(manual, section_id)`** — читает раздел по id: заголовок, путь от корня, список подразделов
(`children`) и полный `text` (в нём markdown-таблицы и ссылки на картинки — плейсхолдер
`__IMG_PREFIX__` заменяется на `/ml-assets/image`, см. ниже).
`open(manual, 'root')` — верхний уровень мануала. Если вместо id передали заголовок, инструмент подберёт
похожие разделы и вернёт список id.

## Перевод на линию поддержки

Мануал `support-redirect-manual.md` описывает три линии (L1 — информационная,
L2 — экспертно-методологическая, L3 — техническая) и куда какие обращения переводить.
Он объёмный, поэтому **в контекст агента сразу не кладётся** — агент достаёт его
инструментом `support_manual()`.

**`transfer_to_support(line, reason)`** — переводит обращение и **закрывает чат**.
Принимает `L1`/`L2`/`L3` (терпимо к `l2`, `2`, «линия 3»). Дальше в чат писать нельзя:
API отвечает `409`, в админке вместо формы появляется плашка. Реального интерфейса
оператора нет — это заглушка (`support.py`).

Логика в системном промпте:

1. Всегда сначала `search` — даже если вопрос кажется не про Портал.
2. Если в базе знаний ответа нет → `support_manual()`.
3. Если мануал подтверждает, что такой вопрос переводится → `transfer_to_support(...)`.
4. Если вопрос вообще не про Портал и в мануале подходящей линии нет → **не переводить**,
   а вежливо сказать, что это не по теме.

Состояние перевода хранится в чате: `redirect_line`, `redirect_reason`, `closed_at`
(видны в `GET /ml-api/chat/<id>`); в SSE приходит событие `redirect`,
а `POST .../message` для закрытого чата отвечает `409`.

LLM: DeepSeek (`DEEPSEEK_MODEL=deepseek-flash`, `OpenAILike`). Каждый ответ — трейс в Langfuse
(`chat-response`, `session_id` = id чата), инструменты и токены видны в админке карточками.
