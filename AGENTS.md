# AGENTS.md

## Дизайн-система (выжимка из референсов)

Правила ниже — единственный источник правды по визуалу HTMX-админки (`ml/templates`, `ml/static/style.css`).
Это **админ-панель**: интерфейс плотный и спокойный, без декоративности.

### Базовые принципы

- **Без закруглений.** `border-radius: 0` у всего: кнопок, полей, карточек, бейджиков, панелей.
  Единственное исключение — круглые точки в бейджиках статусов.
- **Шрифт — Open Sans** (400/600/700). Подключается в `base.html` через Google Fonts.
  Никаких serif и сторонних гарнитур.
- **Primary-цвет — Red** `#DB2B21`. Главное действие на экране — красная заливка, и оно должно быть одно.
- **Типографика плоская.** Размеры отличаются на пару пунктов, а не экспоненциально.
  Рабочий набор — три размера:
  - `0.6875rem` (11px) — мета, подписи бейджиков, служебные ярлыки;
  - `0.8125rem` (13px) — элементы UI: кнопки, поля, списки, дерево, оглавление;
  - `0.875rem` (14px) — основной текст: сообщения чата, текст разделов мануала.
  Больше размеров не вводить.
- **Заголовки не «кричат».** `h1` на странице — не больше `0.9375rem`, вес 700.
  Uppercase — только у вкладок, подписей полей и бейджиков статусов. Больше нигде.
- **Не дублировать заголовки.** Название страницы живёт в одном месте: у раздела — в хлебных крошках.
  Второго хедера-заголовка под шапкой быть не должно.
- **Каркас:** главный хедер — одна строка (`display: flex`, высота `3.5rem`), название слева, вкладки справа.
  Хедер всегда на всю ширину, включая страницы с боковыми панелями.

### Компоненты

**Кнопки**

| Тип | Пример | Normal | Hover | Disabled |
| --- | --- | --- | --- | --- |
| Обводка (`.btn-outline`) | «Отменить», «Скачать инструкцию» | белый фон, рамка и текст `--main-blue` | фон `--pale-blue` | — |
| Primary (`.btn-primary`) | «Сохранить», «Создать котировочную сессию» | фон `--red`, текст белый | фон `--red-dark` | фон и текст `--disabled-*`, `cursor: not-allowed` |
| Текстовая (`.link-btn`) | «Все новости», «Вспомнить пароль» | `--main-blue`, подчёркивание с отступом | — | `--pale-black` |

Высота кнопок — `2.5rem`, кегль `0.8125rem`, вес 600. Иконка у иконных кнопок ставится слева, отступ `0.45rem`.

**Бейджики статусов** (`.tool-status` — единственная реализация в админке)

Точка `0.5rem` + подпись uppercase, `0.6875rem`, вес 700, разрядка `0.08em`. Цвет точки наследуется от статуса:
зелёный — успех/исполнено, красный — отказ/ошибка, оранжевый — ожидание, синий — в работе, серый — архив.
Точка — единственный элемент с закруглением (`border-radius: 50%`).

**Вкладки** (`.tab`)

Uppercase, `0.6875rem`… `0.75rem` при весе 700 и разрядке `0.06em`.
Неактивная — `--pale-black`, активная — `--main-blue` с нижней границей `3px` цвета `--red`.
Фон полосы вкладок — `--pale-blue`.

**Поля ввода**

Заливка `--input-bg` (`#E7EEF7`), рамка того же цвета, паддинг `0.55rem 0.75rem`, кегль `0.8125rem`.
Hover — рамка `--gray-blue`. Focus — фон белый, рамка `--main-blue`. Disabled — заливка `--gray-blue`, текст `--disabled-text`.
У поля всегда есть подпись сверху: `0.8125rem`, вес 700, `--black`. Плейсхолдер — `--pale-black`.

**Хлебные крошки** (`.crumbs`)

Строчные, `0.6875rem`, вес 600, `--pale-black`. Текущий уровень — просто текст, вышестоящий — ссылка `--main-blue`.
Разделитель — `/` цвета `--pale-black`. Крошки заменяют заголовок страницы, а не дополняют его.

### Структура страниц

Публичная часть — на `/` (требует имя в куке), внутренняя админка — на `/admin`
(без идентификации, видит все чаты). REST API — `/ml-api`, картинки — `/ml-assets`.

- `/` — **Поддержка**: сайдбар со списком своих чатов (300px) + панель чата. У чата своего хедера нет —
  заголовок чата виден в списке слева.
- `/login` — идентификация по имени (без пароля).
- `/profile` — имя и выбор роли (поставщик / заказчик / не указано).
- `/knowledge-base` — список мануалов карточками-ссылками на `/knowledge-base/<slug>`.
- `/knowledge-base/<slug>` — оглавление слева, текст раздела в дереве.
- `/admin/` — то же, что `/`, но список содержит все чаты; базы знаний в админке нет.

Шаблоны общие: `chat_list.html`, `chat_panel.html` и `support_layout.html` принимают
`base` (`""` или `"/admin"`), вкладки шапки задаются блоком `nav` в `base.html`.

### Чего не делать

- Не добавлять закругления, тени и градиенты.
- Не плодить размеры шрифта и не выводить крупные заголовки внутри контента.
- Не дублировать название страницы в хедере и в полосе под ним.
- Не использовать uppercase вне вкладок, подписей полей и бейджиков.
- Не добавлять второй primary-кнопки в один блок действий.

## Локальная разработка (ml)

### BPMN-схема процесса

Схема процесса поддержки лежит в `ml/bpmn/support-process.bpmn` и **генерируется кодом**
(`ml/bpmn/generate.mjs`), а не рисуется руками. Менять — только `generate.mjs`,
потом `cd ml/bpmn && npm run build` и коммитить оба файла. Подробности (структура
генератора, как добавить шаг, ограничения `bpmn-auto-layout`) — в `ml/BPMN.md`.

### Сервер уже запущен — новый не поднимать

Приложение `ml` уже работает на **http://127.0.0.1:8011** — запущено из папки `ml/` командой
`uvicorn app:app --host 0.0.0.0 --port 8011 --reload`. Флаг `--reload` сам подхватывает правки
Python, шаблонов и CSS, поэтому для проверки изменений достаточно открыть страницу:

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8011/stats   # 200
```

**Не запускать свой uvicorn на другом порту и не глушить этот** — он общий. Если кажется,
что сервер не отвечает, сначала проверить, что процесс жив (`lsof -nP -iTCP:8011 -sTCP:LISTEN`).

### Скриншоты страниц

Отдельного тула для скриншотов нет: снимаем системным headless Chrome через `bash`,
а результат смотрим тулом `read` — он читает PNG как вложение.

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --disable-gpu --hide-scrollbars \
  --window-size=1280,720 \
  --screenshot=/tmp/shot.png \
  "http://127.0.0.1:8011/stats"
```

Затем `read /tmp/shot.png`.

- Вызов укладывается в 15 секунд — ставьте у команды `timeout: 15`.
- Без куки доступны `/stats` и `/admin` — их и удобнее всего снимать. Страницы `/`,
  `/chats2/<id>` и `/chats/<id>` требуют куку `username`, в headless она не настроена.
- `--screenshot` не умеет hover и клики: состояние, которое в UI открывается по наведению,
  форсируется оверрайдом в `<style>` статичного макета (`file:///tmp/mock.html` с реальным
  `ml/static/style.css`), либо снимается просто открытая страница. Для макета сервер не нужен.
- Данные для скриншота лучше не подмешивать в боевую `chats.sqlite3`, которую держит общий
  сервер: для пустых состояний хватает статичного макета, а существующих чатов — для реальных.
